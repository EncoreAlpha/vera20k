# VMCE 中文待办事项

[中文说明书](vmce-guide.md) · [中文首页](vmce.md) · [English backlog](../vmce-backlog.md)

本页只记录**尚未完成**的工作、已锁定的决定和验收边界。已实现的功能移到文末「已完成」并注明证据边界，详细行为以[中文说明书](vmce-guide.md)为准。**“计划中”不代表当前版本已经支持**。英文台账与本页采用相同编号，更新决定或状态时应同步维护。

## 第一优先：真实联机验收（B36）

B33–B35 的功能已在工作区实现，并有定向测试和本机多进程覆盖。作为玩家可见的完整功能交付前，还须完成以下真实双人、三人、四人会话验收与证据补齐。VMCE 最多四个人类角色，**不引入观察者**。

- 用真实的双人、三人和四人会话覆盖合作、敌对、触发器中途改变结盟、AI 触发胜利、同刻竞争触发、消灭与重新生成、混合胜负，以及全员失败重试。
- 覆盖结算入场动画、准备门、回房间重选角色、随机角色、新人加入与离开、角色数不足、房主开局、末关完成演出和返回主菜单。结果判断必须等待相应动画，而不是把中间帧当作最终画面。
- 验证每端看到的胜负、控制授权、迷雾、下一关身份和确定性校验；覆盖丢包、确认延迟、断线、战役文件不一致和加载失败。
- 验证关间新人：加入并通过整套系列校验后只解锁已确定的下一关，不补领此前关卡；断线重连同样处理；从已解锁中途关新建房间能正常开局。
- 整套系列不一致目前只有定向单测（后台校验、Ready/Go 重新校验、关间解锁），仍缺真实联机采集。
- 同刻竞争触发、盟友判断方向，以及“所属方未设置原版结果标志”时的回退，需有原版证据或明确标注为 VMCE 规则；本机确定性校验不能代替原版行为证明。
- 本机当前构建已通过 2、3、4 人胜利切关、双人失败重试和双人混合胜负切关采集（300 个校验点一致），并核对了各端解锁文件只含指定下一关；标准验收工具已支持 `--players 2|3|4` 与 `2p-final`。这些仍不是跨机器验收。
- 完整片尾仍未观看；网络异常仍未覆盖。

## 第二优先：联机可靠性和准入

- **B10 末关与拒绝消息可靠送达：** 当前 `release_transport` 服务一次后重置带作用域的可靠队列；末关 Go 或拒绝消息丢失时，另一端可能停在结果页。沿用现有传输和重传所有者，确认关键消息已被确认或明确处理发送失败后再释放。分别覆盖末关 Go、关卡不一致/拒绝、退出和对端不响应，并用消息与确认包丢失测试及真实多进程验证。末关部分仍未充分验证；整个 B10 仍未完成。
- **B03 设置失败回滚：** 已实现；只剩真实 LAN 的失败、提示、回滚和退出房间采集。定向单测不能冒充真实采集。
- **B13 客人角色变更广播：** 已实现并有定向测试；仍需真实四人房间中改变客人角色，确认另外两位客人收到更新。
- **B05 全战役预校验：** 联机准入已校验整套系列的地图字节与 `campaign.ini` 身份，并在开局前发现其他地图的字节差异；发现战役时仍只完整校验入口关的战役配置（`PlayerCount`/角色绑定/下一关键），已解锁关卡的配置在发现时校验。剩余工作：选战役时逐关校验所有清单关卡的配置，让后续关的错误在开局前就指出；注意与整套系列校验的性能协调。
- **B11 关卡路径长度：** 现有 LAN 关卡消息的路径上限为 215 字节，超出时会拒绝继续。应设计兼容的传输方式或在准入时明确限制，并测试边界及各平台。
- **B14/B16 错误提示：** 梳理因发现阶段过滤而难以触达的无效战役提示，避免按翻译后的字符串判断错误类型；设置/冻结失败要能指出真正原因，不把所有玩家误记为本地席位。

## 大厅 UI 审查残留

大厅版面与材质修复（见「已完成」）已解决大部分审查项，以下仍未完成。

- **B40 地图详情缓存依赖：** `vmce_map_details` 在每帧的 setup view 里运行，缓存未命中时会解析地图 INI；缓存只在 `network_setup_protocol` 存在时生效，因此没有 protocol 的诊断帧可能每帧重复解析。应把缓存移到始终存在的所有者，或加帧时间保护。
- **B41 合成目录记录：** 下一关不在本地场景目录时，`open_vmce_intermission` 会直接追加一条合成记录；查找忽略系列目录，追加也绕过目录所有者，重复进入时可能累积重复记录。应按 `(系列目录, 地图文件)` 去重，或把「确保下一关在目录中」的职责移入目录所有者。
- **B43 Random 角色不可见：** 新加入的参与者默认是 Random，而 board 只映射具体角色 0..3，Random 玩家没有行、没有 Ready 星；房间里有人时面板可能只显示部分或整片空白。应为每个 Random 玩家显示本地化的 Random 占位行，或加一行「N 名玩家使用随机角色」，不改变任务开始时的分配时机。
- **B45 简报截尾：** 大厅简报画进 `262 - briefing` 高度的框，出现状态条时从 118px 缩到 64px，既无省略号也无滚动，长 `MISSIONMD.INI` 简报会静默丢失结尾。应像放大预览那样在末行加 `...`，或不压缩该框。
- **B46 校验反馈：** 整套系列校验 Pending 时不映射任何内联状态，而 Ready 由 `accept_eligible` 门控，客人会在校验期间看到一个没有反应的 Ready 按钮。应在 Pending 时显示「正在校验战役文件」一类状态，并区分失败/取消。
- **B51 只读可供性：** board 用原生 list frame、纯黄文字和与可编辑 combo 相同的字号，却没有 hover/焦点/选中态，看起来像可交互列表。应使用略暗的值文本色或小提示标明只读，或让某一格真正可交互。
- **B52 简报版式：** 任务简报是唯一没有面板的整宽块（`x=74, w=558`，裸文字），在两个有框面板下形成每行约 90 字符的长行。应像 board 一样加框，或收窄到 board 列、限制在约 450–500px 的阅读宽度。
- **B54 布局稳定：** 状态条显示/隐藏会把简报框在 118px 与 64px 之间切换并移动下方文字（包括后台系列校验完成时）。应始终保留状态条区域，或把状态并入 board 底部，避免阅读位置跳动。

## 已完成及其证据边界

- **B33 逐玩家胜负与消灭后参与：** 已实现。锁定决定：以触发所属方的盟友为胜方、未结盟玩家为败方，触发者也可以是地图 AI；任务中只有地图触发器能改变结盟，玩家不能手动修改；以最先到达原版结算时点的玩家作为全局结束边界，并在该时点按地图/所属方状态判定其他玩家；某所属方未能设置原版胜负标志时按其最近一次地图胜负动作判定（VMCE 规则）；主所属方被消灭不结束任务、不播失败 EVA、不揭全图、不锁操作，之后由其所属方生成的新单位可重新控制；地图授权的 `PlayerNControl` 不随外交改变；不同角色继续要求不同国家；有人获胜即全员可继续，全员失败由客人投票、房主重试，重试保持同一关的冻结角色、地图与随机种子。证据：本机 2/3/4 人胜利切关、双人混合胜负、触发器解除结盟、全员失败重试、末关片尾跳过，并在结果摘要与整套系列准入改动后复跑。跨机器与未查证的原版细节见 B36。
- **B34 关卡间战役房间与重选角色：** 已实现：结算页所有在线客人准备后房主继续；全部玩家回到指定下一关的战役房间，重选角色或保留随机角色，随机分配避开已占角色；可加入/离开，角色数不足时保留房间并阻止开始；该房间不能更换指定下一关；失败重试不经过重选。证据：2/3/4 人切关后的关间房间采集。新人加入与角色数不足的真实联机场景见 B36。
- **B35 本地持久化关卡解锁与整套系列一致性：** 已实现。锁定决定：解锁不要求进入下一关；解锁写入只在所有在线参与者确认本轮结果与下一关身份之后（结果报文把本轮 nonce 与下一关身份摘要绑定，旧格式或摘要不一致的报文在应用前拒绝）；下一关人选由房主从本机已解锁关卡中选择，客人不需要事先解锁；关间新人只解锁已确定的下一关，不补领此前关卡，断线重连同样处理；同一系列内容更新保留解锁，以战役目录名与系列内地图路径识别，目录或路径改名视为新身份；将来若支持分支只解锁实际选择的分支。联机准入校验整套系列（`campaign.ini` 字节、清单顺序、每张地图的相对路径/长度/内容），房主发布摘要，客人在可取消的后台工作线程中校验，未通过或仍在校验时不报告地图可用、不能准备、不能开局；Ready/Go 边界重新校验，所选地图与 `campaign.ini` 仍单独校验，系列 CSF 不参与。证据：2/3/4 人采集后各端 `VmceProgress.json` 只含指定下一关；整套系列不一致只有定向单测，真实联机见 B36。
- **B15 房主配置变化：** VMCE LAN 已实现：房主在 Ready/Go 边界重新计算整套系列摘要并与已发布的摘要比对，不通过就不发 `GO`；冻结开局时仍重新读取 `campaign.ini` 和所选地图。残留：该重新校验完成到 `GO` 实际入队之间的极短窗口内的文件变化不会被发现。
- **B01：** 双人真实失败投票重试已通过，同关重载且 300 个校验点一致；四人重试和真实加载失败提示仍缺验证。
- **B12：** VMCE 已拒绝观察者。已有观察者的房间须先让其转为玩家或离开，才能切换到 VMCE。
- **B30–B32：** 失败统计按冻结玩家/所属方对应；胜利结果板读取已完成关卡和冻结角色，并更新准备状态。双人/三人/四人胜利采集等待了入场动画并使用按钮；双人反序重试核对了统计与颜色，双人混合胜负也已有采集。
- **B24–B28：** 大厅/结果页界面已实现；四行 BC6 是 VMCE 扩展。收入列仅展示正向总收入，不参与模拟决策。**B29** 仅在本地 UI 技能分支，不能作为运行正确性的证据。
- 已修复末关片尾后仍回到 LAN 战役房间的问题；这不等于 B10 的末关消息丢失风险已解决。
- **大厅版面与材质修复（B37–B39、B42、B44、B47–B50、B53、B55、B56）：** 已实现。所属方下拉加宽到 120px（100px 文本面），board 重排到 298..632，国家文字 150、Ready 48、颜色列保留原生锚点；左侧标签与 board 表头统一到 y=14。96/120px 的 combo 单元格改用 VERA 的原生色调字段（共享底色 + 原生 list frame 双像素 bevel），因为原生 combo 面没有这些宽度。用一组调色板替代原先四种黑与金色描边：board/字段底色、中性空位色块、list frame bevel、内联状态的警告色；状态条改为整行宽并对第二行省略。未认领角色显示原生「等待」文本；AI 行不再显示所属方下拉；board 国家/等待文本按原生像素宽度测量，所有截断标记统一为 `...`；删除死代码 `layout.flags`/`VmceLobbyRole.role` 与字面量填充高度。证据：定向测试（`ui::coop_lobby` 5、`skirmish_shell_render::vmce_panel` 3、`app::shell_network_setup` 32、`skirmish_shell_render` 100、`ui::multiplayer_setup` 10）与默认特性构建；未做采集/截图，调色对比与 combo 字段接缝的屏幕观感仍未验证。
